Resumen Ejecutivo

GOON es una plataforma full-stack para operaciones de liga tipo Overwatch: web publica, dashboards autenticados, draft en vivo, overlays para OBS, noticias, OCR de estadisticas y utilidades de base de datos.

Tablas SQL / Modelos Prisma

Diccionario organizado de las entidades persistidas. Prisma usa PostgreSQL con DATABASE_URL y DIRECT_URL.

backend/prisma/schema.prisma

Tournament

Raiz competitiva
  • idIntPK autoincrement
  • nameStringNombre del torneo
  • startDateDateTimeFecha inicial
  • stateTournamentStateSCHEDULED, ROUNDROBIN, PLAYOFFS, SEMIFINALS, FINALS, FINISHED
  • matchesMatch[]Partidos del torneo
  • teamsTeam[]Equipos inscritos

Team

Roster y standings
  • idIntPK autoincrement
  • nameStringNombre del equipo
  • logo / rosterString?Assets visuales
  • stateTeamStateACTIVE o ELIMINATED
  • victories / defeatsIntRecord de serie
  • mapWins / mapLosesIntDiferencial de mapas
  • tournamentIdIntFK a Tournament
  • discordRoleIdString?Integracion Discord
  • bannerLeft / bannerRightString?Banners para overlays
  • membersMember[]Jugadores o usuarios del equipo

Member

Usuarios y roles
  • idIntPK autoincrement
  • nicknameStringNombre visible
  • userString @uniqueLogin unico
  • passwordHashStringHash bcrypt
  • roleMemberRoleADMIN, MANAGER, CAPTAIN, EDITOR, DEFAULT
  • profilePicString?Avatar
  • rankIntRanking interno
  • teamIdInt?FK opcional a Team
  • obsWebsocketUrl / passwordString?Ajustes OBS por usuario
  • playerStatsPlayerStat[]Estadisticas registradas

Match

Partido en vivo
  • idIntPK autoincrement
  • type / statusMatchType / MatchStatusFase y estado operativo
  • bestOfIntFormato de serie
  • startDateDateTime?Programacion
  • tournamentIdIntFK a Tournament
  • teamAId / teamBIdIntFK a Team con relaciones TeamA y TeamB
  • teamAready / teamBreadyIntCheck-in de capitanes
  • pointsTeamA / pointsTeamBIntPuntos generales
  • mapWinsTeamA / mapWinsTeamBIntMarcador de mapas
  • gameNumberIntUltimo juego completado
  • semanas / titleInt? / String?Semana y titulo
  • mapsAllowedByRoundJson?Pool por ronda/juego
  • mapResultsJson?Historial de mapa, ganador o empate
  • map timer / pauseDateTime? / BooleanTimer y pausa operativa
  • draftDraftTable?Draft unico por match
  • allowedMapsMap[]Relacion many-to-many

DraftTable

Estado draft
  • idIntPK autoincrement
  • matchIdInt @uniqueUn draft por partido
  • currentTurnTeamIdInt?Equipo al turno
  • phaseStringSTARTING, MAPPICKING, BAN, PLAYING, ENDMAP, FINISHED
  • phaseStartedAtDateTimeBase del timer
  • bannedHeroesJsonHeroes bloqueados
  • pickedMapsJsonMapas elegidos
  • currentMapIdInt?Mapa actual
  • actionsDraftAction[]Log ordenado de picks/bans/skips

DraftAction

Historial draft
  • idIntPK autoincrement
  • draftIdIntFK a DraftTable
  • teamIdIntFK a Team
  • actionDraftActionTypeBAN, PICK o SKIP
  • valueInt?ID de mapa o heroe, si aplica
  • gameNumberIntJuego al que pertenece
  • orderIntOrden cronologico
  • createdAtDateTimeFecha de accion

Map

Contenido OW
  • idIntPK autoincrement
  • typeMapTypeCONTROL, HYBRID, PAYLOAD, PUSH, FLASHPOINT
  • descriptionStringNombre o descripcion del mapa
  • imgPathStringImagen servida por backend o blob
  • matchesMatch[]Pool permitido many-to-many

Hero

Contenido OW
  • idIntPK autoincrement
  • nameString?Nombre del heroe
  • roleHeroRoleTANK, DPS, SUPPORT
  • imgPathStringIcono del heroe
  • heroGiftString?Video/GIF opcional

PlayerStat

Stats por mapa
  • idIntPK autoincrement
  • damage / healing / mitigationIntTotales del scoreboard
  • kills / assists / deathsIntKDA base
  • gameDurationIntDuracion en segundos
  • Per10 metricsFloatdamagePer10, healingPer10, etc.
  • mapType / roleMapType / HeroRoleContexto competitivo
  • userIdIntFK a Member
  • matchIdIntFK a Match
  • gameNumberIntMapa/juego dentro del match

News

Contenido editorial
  • idIntPK autoincrement
  • titleStringTitulo
  • contentStringMarkdown/contenido
  • imageUrlString?Imagen principal
  • createdAt / updatedAtDateTimeAuditoria simple

LeaderboardOverlayAsset

Overlay settings
  • idIntPK autoincrement
  • matchIdInt @uniqueFK unica a Match
  • backgroundImageUrlString?Fondo del overlay
  • settingsJson?Configuracion visual persistida
  • createdAt / updatedAtDateTimeAuditoria
  • onDeleteCascadeSe borra con el match

Relaciones de Datos

Lectura directa del schema Prisma. Las flechas indican dependencia funcional o FK principal.

Un torneo agenda partidos.

Un equipo puede estar en ambos lados del match.

Un draft unico por partido.

Acciones ordenadas del draft.

Equipo que ejecuta pick, ban o skip.
MatchPlayerStat[]
Stats registradas por match y gameNumber.

Jugador propietario de estadisticas.

Entrada del servidor

backend/app.js carga variables, configura CORS/body parser, sirve assets estaticos, monta rutas, verifica /health, conecta Prisma y arranca el worker de draft cada 3 segundos.

Base de datos

backend/config/prisma.js centraliza Prisma Client. Las migraciones viven en backend/prisma/migrations y los seeds en backend/prisma y backend/scripts.

Flujos Principales

Procesos del sistema desde la accion del usuario hasta la persistencia.

Login y roles
Usuario envia credenciales

Frontend llama login(user, password) hacia POST /member/login.

Backend valida

memberController.login busca Member.user, verifica hash y genera JWT.

Sesion local

loginAndPersist guarda token y usuario en goon.live.session.

Middleware protege

authMiddleware carga req.user; admin, manager, captain y editor restringen acciones.

Draft map pick y hero ban
Crear draft

Manager/admin llama POST /draft/:matchId; se crea DraftTable unico.

Map picking

startMapPicking coloca fase MAPPICKING, turno y timer.

Pick de mapa

pickMap valida equipo, pool permitido por mapsAllowedByRound o tipo de mapa, y graba DraftAction(PICK).

Ban phase

startBan abre fase BAN; cada banHero guarda DraftAction(BAN).

Worker de timeout

startDraftTimeoutWorker(3000) auto-aplica skip/pick random cuando vence el turno.

Resultado, standings y schedule
Manager registra mapa

submitMatchResult recibe winnerTeamId o empate.

Transaccion Prisma

Actualiza Match.mapWinsTeamA/B, gameNumber, mapResults y readiness.

Record de equipos

Incrementa Team.mapWins/mapLoses y, al cerrar serie, victories/defeats.

Leaderboard

/team/leaderboard ordena por victorias, diferencial de mapas y id.

Frontend y overlays

Standings, home, schedule y leaderboard overlay consumen esos endpoints.

OCR de estadisticas
Subida de imagen

Manager usa /playerStat/upload-match-preview con multer.memoryStorage().

OCR

services/googleVision extrae texto y palabras; services/playerStat parsea filas.

Normalizacion

Detecta duracion, mapas, nicknames, roles y metricas per-10.

Preview y correccion

La UI puede revisar filas antes de confirmar.

Persistencia

confirmBatchFromPreview crea multiples PlayerStat para matchId y gameNumber.

Overlays de broadcast
Editor de assets

/assets-edition actualiza settings del overlay con /overlay-assets/leaderboard/:matchId.

Datos en vivo

Overlays leen match, teams, draft, map pool, rosters y assets.

Render OBS

Las rutas /overlay/* son paginas Next pensadas para browser source.

Launcher

migration-uidesign/launcher integra flujo local Electron/OBS websocket.

Contenido editorial y OW
Mapas y heroes

/admin-dashboard/overwatch-content consume /map y /hero.

Uploads

utils/contentImageUpload gestiona imagenes de contenido.

Noticias

Editor/admin usa /news/create, /news/update/:id y /news/delete/:id.

Consumo publico
